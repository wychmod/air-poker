# 发牌与对手策略 Spec

用户已于 2026-10-25 确认按「整局基准 → 多轮选牌 → 下注判断 → 发牌决策」推进。本轮在该范围内实施，规则不变。

## 目标与需求

- F1：固定种子整局模拟复用真实引擎，支持旧策略、新策略、被动和激进基准；同一发牌交换双方测试。记录终局胜负、空气收益、无解、灾厄和每局账目校验。
- F2：选牌兼顾当前强度、消耗己方实体牌后剩余数字的可解性和牌力。玩家选牌前锁定，不读取玩家隐藏信息。
- F3：下注使用公开数字的有限候选模型、底池收益与灾厄损失；解释模型概率的假设，不称其为真实胜率。
- F4：在策略评估后决定是否改变发牌。数字总和接近不等于整局公平；证据不足时保留现行规则并明确结论。

## 约束

原生模块、无运行依赖；固定计算预算；不改变至多三个界面推荐、半池上限、呼吸、记录格式或信息隔离。不增加难度选择或跨局学习。保留工作区无关修改。

## 验收标准

- AC1 / F1：同一种子与配置统计可复现，换边确实交换同一组数字；整局到达 summary，记录验证通过且 50 罐守恒。
- AC2 / F2：回归案例证明可保留后续解；无解仍有合法降级；输入不被修改，私有信息不进入决策。
- AC3 / F3：高成本弱牌弃牌、强牌合法加注，灾厄模型能改变边界决定；不能越过下注上限。
- AC4 / F4：记录分阶段及独立样本结果、计算开销与发牌保留或调整的理由。
- AC5：npm run check 通过，真实浏览器完成对局且无脚本错误；未执行项目如实记录。
