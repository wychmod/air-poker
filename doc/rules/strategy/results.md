# 发牌与对手策略实施结果

2026-10-25。用户确认按整局基准、选牌、下注、发牌决策顺序实施。规则与记录格式保持兼容，默认对手已接入新策略。

## 复现方式

```sh
npm run evaluate:strategy -- --mode baseline --seeds 100 --start-seed 10001
npm run evaluate:strategy -- --seeds 100 --start-seed 10001
```

每条命令按组合逐行输出统计，报告写入 output/harness/strategy-baseline-10001.json 和 strategy-full-10001.json；这些文件不提交。--slow 使用 55 秒构造节奏，另存带 -slow 后缀的报告；正常节奏为选数字 1 秒、构造 12 秒、双方下注行动 600 毫秒。对手通过引擎真实行动截止执行。可用 --seeds 和 --start-seed 控制规模。

两份独立验证共 2,000 局，来自相同 100 个种子（10001–10100），每个组合交换同一组双方数字，各 200 局。发牌与策略随机流分离。固定旧算法保存在 scripts/strategy/legacy.js；策略仅获得自己的数字、成手与公开信息。每个动作检查账户，总终局记录通过 isCompletedRecord。报告保留核心源码 SHA-256；验证完成后核对与当前源码一致。

得分率 =（胜局 + 0.5 × 平局）/ 局数。近似 95% 区间按每个交换持牌的两局聚为一个样本计算，不把 200 局当作 200 个独立发牌。meanAirGain 是进入耐息前未开余额减初始 24，含此期间额外开罐与灾厄损失；它不是最终剩余供气。

## 选牌与下注的实际行为

选牌从每个数字的至多 12 个候选中取最多三种代表：最强、同强的另一实体花色方案、不同点数组成。对当前牌型采用完整踢脚序列，移除候选后逐一检查自己的其他未用数字。当前牌力 + 0.04 × 剩余数字牌力总和，每个无解剩余数字计 -2.5；相同评分随机。局部缓存仅存活于一次决策，最多评估十五个成手。它不枚举所有实体花色，不联合分配未来全部成手，也不知道对手未来会弃掉什么。

固定回归只剩 13 张实体牌、数字为 37 和 25：旧版先组两对 A 与 10，导致 37 无解；新版先组两对 10 与 2，仍保留 25 的合法成手。该测试验证具体资源规划能力，不代表所有局面都会更强。

下注将公开目标的至多 12 个强候选按牌力加权，玩家本轮加注次数增加强牌权重。根据模型的赢、平、输与重叠失败概率，计算相对立即弃牌的额外 AIR：期望底池回款 - 本次成本 - 重叠失败时实际可烧储备。加注假设会被跟注，不虚构迫使玩家弃牌的收益；比较跟注和 1、半上限、上限三种增量，同值随机。无成手时无压力过牌、有压力弃牌。模型是有限候选假设，未经真人数据校准，不是真实胜率或最优博弈解。

开发种子 1–40 的第一版使用 0.35 前瞻权重，仅改选牌得分率 44.375%；据此降低当前牌力的牺牲，种子 41–80 复核，再冻结参数进入独立验证。独立样本未用于再次调参。开发日志在 output/harness/strategy-development*.log。

## 发牌决策

保持现行「十组证明成手 → 最小化双方数字总和差 → 随机分配双方」规则。对种子 10001–11000 的 1,000 次发牌，966 次总和差不超过 1，最大差 5；开局最强完整牌型及踢脚比较，玩家更强 463 次、对手更强 460 次、相同 77 次。这里比较的是完整牌型，不能与早先仅比较四条 / 同花顺等级的百分比混用。

数字总和不是牌力指标；最强牌型差异也是随机局势的一部分。现有结果不足以支持通过重发、强制双方牌型相同或减少强牌来改变玩法。新版自我对战区间包含 50%，但旧版自我对战仍有有限样本、角色行动顺序与随机流影响，不能据此宣布完全公平。要研究发牌规则变化，应另设交换行动角色、更多随机源与候选规则的对照实验。
