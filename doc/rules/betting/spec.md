# 多轮下注需求

日期：2026-10-24。用户在独立持牌修正后要求继续“下一项修改”，对应核对报告中建议的多轮下注。本轮按此授权直接实现；以下文件是实施与验收记录，不声称用户逐份审阅过文档。

## 背景与目标

把玩家一次动作、CPU 自动匹配即摊牌的体验流程，改为可观察的交替下注。保留独立数字牌、CPU 预先成手、共享弃牌和当前数字版呼吸/终局。

## 功能需求

- F1：首轮小数字先动，后续逐轮交替；数字相同采用开局该次随机决定，并公开说明。
- F2：双方轮流行动。只有无应跟金额时可过牌；跟注补齐差额，之后仍轮流，双方连续过牌才结束；有人弃牌立即结束。
- F3：加注表示“先跟齐，再增加”。加注增量至少 1，至多补齐跟注后底池的一半，并受双方可匹配资源封顶；不套用德州最小加注。
- F4：全押也受半池限制，只能投入双方可匹配的上限，不能绕过加注限制；双方已匹配且一方没有可下注 AIR 时直接摊牌。
- F5：CPU 基于自身冻结成手、玩家公开数字、公共弃牌、资金和下注历史选择过牌、跟注、加注、弃牌或合法全押，不能读取玩家私牌及未出数字。
- F6：每次玩家行动有新的 30 秒；无压力超时过牌，有应跟额超时弃牌；CPU 独立短暂思考。语言、规则查看不续时，后台恢复不重置截止时间，重开清理旧回调。
- F7：界面显示行动方、双方投入、应跟额、加注范围及合法动作；重复旧按钮和回调不得跨行动重复生效。

## 非功能与范围

资金保持非负整数，底池与投入一致，正常结算守恒，灾厄仅烧实际额。纯规则/状态机不调用 DOM 或计时器，无运行依赖。UI 风格、页面提案、原作上层失败判例和真实呼吸不在本轮实现范围。未提交改动保留，不提交或推送。

## 验收标准

| 需求 | 可观察通过条件                                                                             |
| ---- | ------------------------------------------------------------------------------------------ |
| F1   | 小数字先动、同数可复现随机、第二到第五轮首动交替                                           |
| F2   | 一次过牌不自动结算；面对加注不能过牌；跟注金额准确；跟注后两次过牌结束；任一方弃牌胜负正确 |
| F3   | 双方底注各 1，依次加注 1/2/4、跟注后各投入 8；超过上限/非法输入不改状态                    |
| F4   | 小资源和全押不产生负数/边池；不能以全押绕开半池；匹配耗尽只结算一次                        |
| F5   | 同公开信息、同随机源的 CPU 响应相同，不随玩家隐藏候选变化                                  |
| F6   | 新玩家行动重置 30 秒；语言/规则不续时；超时只生效一次；重开和后台恢复无旧动作              |
| F7   | 按钮禁用与引擎合法动作一致，旧 turnId 失败且资金不变                                       |

## 规则依据与具体化

依据 [日文整理](https://royal2627.ldblog.jp/archives/48002529.html) 的半池上限、首动交替、30 秒、双方过牌，以及第一轮“跟注并 MAX 加注”达到双方各 8 的示例。采用先补齐应跟额再计算半池，可重现该示例；该资料明确记述最终跟注后双方过牌。本版 AIR 只能为整数，取整向下；相同数字首动、可匹配全押及超时处理是明确的数字版约定。
