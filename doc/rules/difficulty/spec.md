# 三档难度与融合对手策略 Spec

状态：用户已于 2026-11-05 批准并完成实施。本文件是本轮设计与验收依据；实际结果见 [Checklist](checklist.md) 和 [策略实施结果](../strategy/results.md)。

历史方案说明：早期页面方案曾设想独立挑战入口、展开后的契约选择和默认无契约。后续需求取代了这部分交互；它只作为设计过程记录，不是当前页面或验收预期。当前新局固定为新手 `none`、中等 `comeback`、困难 `perfect`；`no-fold` 仅兼容带有该契约的旧记录，旧 `air-poker-contract` 偏好不参与新局。

需求来自用户本轮提出的「融合现有几种设定，提供新手、中等、困难，让对手更智能」。当前行为以 [对手入口](../../../game/opponents.js)、[选牌规划](../../../game/ai-planning.js)、[下注模型](../../../game/ai-betting.js)、[浏览器入口](../../../app.js) 和可执行测试为准。

## 背景与目标

当前精密、深渊、镜像使用相同构牌策略，后两者主要通过随机增加跟注与加压形成区别。进攻频率并不能直接代表策略强度；首页还同时展示契约，第一次选择时需要理解多组风格和目标。

目标是让玩家直接选择三档挑战强度。每档都能结合当前局面使用价值下注、保守控制和有限施压，难度差别来自规划能力、风险判断与公开信息利用，打法随局势变化。

## 方案比较

| 方案                         | 行为与取舍                                                                   |
| ---------------------------- | ---------------------------------------------------------------------------- |
| 推荐：统一策略，三档能力预算 | 首页选择明确，构牌与下注共同区分难度；需要验证策略收益、信息隔离与运行开销。 |
| 现有三种风格分别对应三档     | 改动较少，仍主要体现风格与进攻频率，难度排序缺少依据。                       |
| 自动判断玩家水平并升降难度   | 可减少初次选择，需要额外校准与反馈机制，玩家对当前挑战强度的预期更难保持。   |

本草案采用第一种方案，选定的难度在本局保持固定；对手仍会根据本局公开局面调整行动。

## 功能需求

- F1：首页提供「新手 / 中等 / 困难」与对应英文选项，默认中等。每档给出一句易懂的挑战说明，选中状态清楚；选择可跨刷新保存。
- F2：取消独立契约选择，固定映射为新手 `none`（标准对局）、中等 `comeback`（逆风翻盘）、困难 `perfect`（全胜压制）；各档说明写明目标。`no-fold` 仅为旧记录兼容目标；旧 `air-poker-contract` 偏好不读取、不写入，也不改变新局映射。
- F3：三档共用融合策略。行动同时考虑己方成手、公开目标、合法费用、底池、未开空气与灾厄风险；根据局面在价值下注、谨慎应对和适度施压之间调整，避免固定套用某一种人格或无条件重复加注。
- F4：新手优先理解和处理当前回合，减少后续构牌规划与复杂下注尺寸，给玩家更宽松的压力。所有能构造出的成手仍须有效，不以故意提交无效牌或超时制造简单难度。
- F5：中等保留当前有限前瞻与牌力、费用、灾厄判断，融合受收益和资源约束的打法变化。弱牌面对高成本时能止损，强牌有合理投入机会。
- F6：困难更充分权衡消耗实体牌后剩余数字的可解性，并根据本局玩家已经公开的跟注、加注、过牌和弃牌调整后续决策。公开行为不足时保守使用基础模型，适应不能简化为「玩家加注就必定反加」或「玩家过牌就必定加注」。
- F7：开场、牌桌、结果、复盘、导出与分享均反映本局实际选定的难度和固定契约。旧版记录保留原人格与契约显示；旧版人格偏好迁移到中等，不改写历史记录。

## 非功能需求与约束

- N1：对手在玩家选择前锁定自己的数字与成手。规划仅使用己方未公开数字和公共弃牌；下注可使用己方成手、已公开数字、账户与已发生的公开行动。禁止读取玩家未公开数字、私牌、草稿与来源证明。
- N2：使用固定上限的搜索与统计预算；原生 JavaScript、无新增生产依赖或在线模型服务。桌面与窄屏浏览器实测计算耗时并记录条件，不能把未测性能写成保证。
- N3：难度不改变发牌、每方 25 AIR、五轮与耐息、构造与行动时限、半池加注上限、资金守恒或玩家至多三个推荐。
- N4：相同输入与随机种子可复现；策略不得修改输入。公开历史适应仅限本局，重开清空，不影响最近完成局归档。
- N5：键盘与触屏均可选择难度；中英文窄屏布局保持开始按钮和各档目标说明可读、可达。

## 本轮边界

不引入跨局画像、隐藏升降难度、读取私牌、改变发牌来调整强弱、联网训练、无限搜索或额外游戏规则。保留现有画面和动效方向，调整范围为设定入口、策略及其记录展示。

## 验收标准

- AC1 / F1：首页三档选择、键盘操作、中英文、刷新保留均通过；非法或旧版偏好安全回退到中等。
- AC2 / F2：首次进入只展示三个难度选项，无独立挑战入口或契约控件；新手/中等/困难分别映射 `none` / `comeback` / `perfect`，说明和新局记录一致。旧 `air-poker-contract` 偏好不能覆盖映射，`no-fold` 只在旧记录中兼容；正常弃牌仍可操作。
- AC3 / F3：固定局面证明同一档会在不同费用、牌力和空气储备下调整决定；施压不会越过收益与风险边界，所有输出均可被真实下注状态机接受。
- AC4 / F4：新手与中等有可复现的构牌规划或下注差异，能完成整局；有解时不因难度主动制造无效成手。
- AC5 / F5：回归验证弱牌高成本止损、强牌合理投入、灾厄改变边界决定，以及后续数字可解性的保留。
- AC6 / F6：固定相同己方牌与当前费用，改变本局公开行动样本可改变困难的模型或行动倾向；少量样本有回退，隐藏字段的变化不影响决定。新局不继承上一局样本。
- AC7 / F7：至少从每个难度开始并完成一局，核对开场、牌桌、结果、复盘、JSON 与双语分享一致；旧人格归档仍显示旧名且可导出。
- AC8 / N1–N4：策略输入隔离、合法动作、固定种子复现、整局完成与 50 AIR 账户守恒回归通过。非法动作、重复动作与计时边界仍由引擎拒绝或处理。
- AC9 / 难度效果：开发与独立验证使用不同固定种子，统一发牌并交换持牌，以同一基准策略对三档做整局比较，报告胜平负、进入耐息前空气收益、无解与灾厄、计算开销和样本局限。验收依据包括从新手到困难的总体挑战强度趋势与具体决策回归；趋势不成立时继续调整，不能仅凭加注次数宣布困难更强。
- AC10 / N2、N5：完整工程检查与相关浏览器回归通过；桌面和手机窄屏完成难度选择、组牌、下注、终局与复盘。明确区分自动验证、实际浏览器检查及尚未执行的真机体验。

## 已确认的产品取舍

默认选择中等。后续用户明确要求取消独立挑战选择，将标准对局、逆风翻盘和全胜压制固定绑定到新手、中等、困难；「不弃之誓」仅为旧记录兼容目标。此后续决定已实施，并取代早期独立挑战入口/展开/默认无契约方案。以当前代码和本文件为准。
