# 三档难度与融合对手策略 Plan

状态：用户已于 2026-11-05 确认并完成实施。依据为 [获批 Spec](spec.md)；实现与验收结果见 [Checklist](checklist.md)。

历史方案说明：早期曾规划独立挑战入口、可展开的契约选项和默认无契约。后续固定映射需求已取代该交互；以下设计记录描述当前实现，旧方案不再作为实现或验收要求。

## 架构概览

沿用原生 ES modules 和引擎注入对手的接口。新增两个职责单一的纯模块：难度标识与预算、公开下注观察。既有构牌与下注模块接收可选策略配置，对手工厂将三档配置绑定到统一策略；浏览器入口负责偏好迁移、选择与显示。

引擎在合法下注动作被接受时维护本局公开动作的有限副本，供对手读取。该副本不来自记录器，不参与扣款、结算或计时；记录器仍只记录已发生事实。界面只消费选定难度和公开快照，不接触对手模型或隐藏信息。

需求归属：F1–F2 由首页与应用入口负责；F3–F6 由策略工厂、构牌、下注和公开观察负责；F7 由 mode 元数据与统一显示转换负责。

## 核心数据与接口

### 难度与兼容数据

- 新局难度 ID 为 `beginner`、`medium`、`hard`，默认 `medium`。
- `game/difficulty.js` 导出 `DIFFICULTY_IDS`、`DEFAULT_DIFFICULTY`、`isDifficultyId(value)`、`normalizeDifficulty(value)`、`difficultyPolicy(id)`。仅持有冻结的常量和配置，无运行模块依赖。
- `normalizeDifficulty` 对旧人格 ID、未知值和空值回退到中等；它用于新局和偏好，不用于改写历史记录。
- 浏览器视图使用 `view.setup = { difficulty }`，不保存独立契约选择或展开状态。
- 新局继续写现有记录字段 `mode = { opponent: difficultyId, contract }`，其中 contract 固定映射为 beginner→none、medium→comeback、hard→perfect；不修改记录 schema 或账户结构。
- `no-fold` 只保留给带有该契约的旧记录；新局不会映射到该值。旧 `air-poker-contract` 偏好不读取、不写入，对新局契约没有影响。
- 旧记录的 `mode.opponent` 为 `analyst`、`abyss`、`mirror` 时保留原显示。无 mode 的旧记录维持原来的默认人格说明，不据此声称当年选择过中等难度。

### 对手与策略入口

- `createOpponent(id = DEFAULT_DIFFICULTY)` 返回 `{ id, choosePlay, chooseBet }`。三个新 ID 绑定融合策略；旧 ID 继续兼容既有显式注入调用，但不出现在新局选择列表。
- `choosePlay(targets, usedTargets, discard, random)` 的既有四参数契约不变。工厂闭包向 `choosePlannedPlay(targets, usedTargets, discard, random, policy)` 追加第五个可选参数。
- `chooseValueBet(input, random, policy)` 增加第三个可选配置参数。`input` 保留 `hand`、`opponentTarget`、`discard`、`options`、`history`，新增可选 `observations`。
- 不传 policy 时保留当前 `game/ai.js` 导出函数的语义、候选预算和随机数调用顺序，保持现有策略基线与显式注入策略可复现。浏览器新局通过工厂使用三档配置。
- 配置与观察在每次调用中只读，不在工厂、策略模块或全局变量中保存跨局学习状态。

### 公开观察

`game/ai-observation.js` 提供纯函数 `makeBetObservation(before, options, event, timedOut)` 和 `summarizePublicActions(observations)`。

观察结构仅包含以下公开值：

| 字段                              | 来源与含义                               |
| --------------------------------- | ---------------------------------------- |
| `sessionId`、`round`、`attemptId` | 动作接受前的会话、回合和尝试标识         |
| `turnId`、`actor`、`action`       | 已接受事件对应的旧行动序号、行动方和动作 |
| `paid`、`raised`                  | 已接受事件的实付与增量                   |
| `toCallBefore`、`maxRaiseBefore`  | 动作发生前的公开应跟额与合法加注上限     |
| `timedOut`                        | 是否由超时处理自动产生                   |

不直接保存整个 before/state、候选、牌面或数字手牌。`before` 在这里是引擎显式构造的会话、回合、尝试标识对象，不是完整权威状态。

引擎私有数组 `betObservations` 最多保存最近 64 个已接受动作，按 `sessionId + turnId` 唯一识别。初始化与 `reset()` 清空；非法或重复动作不追加。调用下注策略时传独立副本，不额外加入 `getState()`，也不从 recorder 反向取数据。

## 构牌规划

### 统一候选和效用

复用实体牌候选生成、完整牌型比较及现有局部缓存。候选必须匹配目标和、互不重复并且未使用；仍在玩家选数字前锁定。界面推荐继续至多三个。

根候选的基础效用使用当前完整牌型强度与剩余己方数字的可解性。不同花色方案按实体 ID 区分。无解时只在所有未使用数字均找不到有效候选后返回合法失败；计算预算耗尽不能被当作数学无解。

### 三档预算

| 难度 | 根候选                                | 后续规划                                          | 变化来源                                                       |
| ---- | ------------------------------------- | ------------------------------------------------- | -------------------------------------------------------------- |
| 新手 | 每个数字最多 3 个合法候选             | 只比较当前牌力                                    | 在当前评分接近的方案中使用传入随机源选择；不故意提交无效手牌   |
| 中等 | 每个数字最多 12 个候选，至多 3 个代表 | 沿用当前一层剩余数字评估                          | 保留对后续无解的惩罚，同分或近同分选择有限变化                 |
| 困难 | 每个数字最多 12 个候选，至多 3 个代表 | 根候选完成基础打分后，对最优 4 个根分支多展开一步 | 同时评估下一次己方出牌后的其他数字可解性，使用实际实体移除结果 |

困难规划深度为两次己方构牌，最多 4 个根分支、每个后继数字最多 3 个代表；一次决策最多 256 次候选生成缓存未命中。缓存键由目标、排序后的已移除实体 ID 和候选上限组成。每个根分支先完成基础评估；只有全部 beam 分支完成同等深度评估时才采用深化结果，否则统一回退本次所有根候选的基础分，避免混合不同深度的分数产生顺序偏差。未探索分支不能记作失败。

game 内以计数控制预算，不读取平台时间。开发工具记录真实耗时。困难仅规划自己的资源消耗，不预测对手未公开数字或假定对手未来的弃牌。

## 统一下注与适应

### 有限模型与合法动作

继续由 `estimateShowdown` 基于对方当前已公开数字生成有限候选模型，使用完整牌型比较与实体重叠计算模型胜、平、负和重叠失败权重；这些值不对外称为真实胜率。

候选动作仅来自 `getBetOptions`：无压力过牌、有压力跟注、合法加注和弃牌。全押仅作为与同一合法加注成本等价的表达，不单独扩大动作空间。无有效成手时沿用无压力过牌、有压力弃牌。

每个付费动作先使用现有 `betValue` 计算相对现在弃牌的模型 AIR 收益，再计算 `score = betValue - riskWeight × cost² / max(1, reserve)`，其中 `cost = toCall + raise`。该非负风险项随投入占剩余储备比例增加。不同难度通过候选尺寸、近优随机范围及风险系数区分，不把明显负收益加注随机覆盖成进攻动作。

| 难度 | 候选增量                                       | 决策侧重                                                     |
| ---- | ---------------------------------------------- | ------------------------------------------------------------ |
| 新手 | 最小合法增量                                   | 低压力，主要处理当前回合；面对不利费用能弃牌                 |
| 中等 | 最小、半上限、上限，去重                       | 沿用当前价值与灾厄判断，在收益接近的合法动作中有限混合       |
| 困难 | 中等尺寸并增加四分之一、四分之三上限，取整去重 | 结合经平滑的公开行为调整候选权重与风险，仍满足收益和资源约束 |

过牌或跟注在接近最优时也可被选中，避免强牌始终立即使用同一加注尺寸。任一付费动作在当次最终模型下的 `betValue` 必须非负：困难先完成公开行为的平滑调整，再计算这一门槛，随后扣除储备风险项选择动作；不另外要求适应前的旧模型同样非负。收益不足时采用合法过牌或弃牌，不能靠随机分支绕过限制。策略配置中的阈值只用开发样本调整，随后冻结再进入独立验证。

固定配置初值集中在 `difficultyPolicy`：新手、中等、困难的 `riskWeight` 分别为 0.35、0.12、0.08，下注近优分差分别为 0.20、0.10、0.05 AIR。选取满足收益门槛且分数距最优不超过该差值的合法动作，再用传入随机源选择。新手构牌只在当前牌力差不超过 0.20 的根候选中变化。上述初值可按开发基准调整；预算、平滑公式、收益门槛和信息边界不能随调参改变。

### 本局公开行为统计

统计只读取 `actor === 'player'` 且非超时的公开观察。主要维度为：允许加注时的主动加压比例、面对应跟额时的继续比例、面对应跟额时的弃牌比例、无应跟额时的过牌比例。分母采用对应机会数，规则禁止加注不能被解释为缺乏攻击性。

使用带先验的平滑比例 `(次数 + 先验样本数 × 先验比例) / (机会数 + 先验样本数)`，初始先验样本数为 6；实际观察权重另以 `min(机会数 / 12, 1)` 限制，少量样本不会引发剧烈改变。四个比例分别计算，不能用同一个总行动数作所有分母。

困难将频繁主动加压的玩家视为其单次加注信息量较低，将很少加注的玩家的加注视为较强证据，在有限范围内调整模型强牌权重；继续/弃牌和过牌行为用于调整收益接近时的尺寸与风险偏好。所有调整均受配置上下界与基础收益门槛约束。中等只利用当前轮公开压力，新手不做跨轮适应。

当前轮 `history` 和 `observations` 对同一动作只计一次：有观察时以观察统计习惯，history 仅提供当前压力序列；缺少观察的旧调用退回当前基础模型。`event.called` 对弃牌也可能大于零，禁止用该字段直接计作已跟注；只按 `action` 与 `toCallBefore` 识别行为。自动过牌和自动弃牌不用于推断主动偏好。

不额外假设玩家会因加注弃牌，不把未校准的弃牌率当作确定的额外收益。每次决策只从有限候选动作中选择，不修改玩家状态或下注规则。

## 引擎与模块交互

1. 应用读取新难度偏好，归一化后调用 `createOpponent(difficulty)`，将相同难度和契约写入本局 mode。
2. 引擎在准备回合时通过原四参数接口请求己方选牌，锁定结果后才等待玩家选择。
3. `resolveBet` 先保存该次动作的公开标识和合法选项，调用 `applyBetAction`；拒绝则直接返回，观察与账户均不变化。
4. 动作被接受后，以接受前的标识和选项、接受后的 event 生成观察，再更新私有数组；记账仍走现有 recorder。观察模块不调用 recorder。
5. `actCpu` 将当前白名单输入和观察数组副本交给融合下注策略。策略输出仍由引擎验证并处理，不直接扣款。
6. 完成局沿用原归档。新局模式明确为难度，旧局模式保持原人格，显示与分享从正在查看的记录读取，不从首页新设定推断。

`makeBetObservation` 不新增记录事件、不推动阶段；丢弃数组中最旧样本也不会删除正式事实。旧 turn、重复确认和后台恢复继续由现有引擎序号与时间处理防护。

## 界面、偏好和记录显示

- 新偏好键为 `air-poker-difficulty`；合法新值优先。新键缺失时将旧人格偏好迁移为中等，不复用旧名作为新难度。存储失败保留内存选择。
- 首页使用 `choose-difficulty` 与 `aria-pressed` 委托动作；档位说明同时显示固定目标。旧 `air-poker-contract` 键不读取、不写入；新局目标仅由难度映射决定。
- 角色称呼统一为「对手 / Opponent」，难度在独立标签说明。旧记录仍展示精密、深渊、镜像作为历史模式。
- `ui/modes.js` 增加难度中英文文案和只列三档的选择数据，保留旧人格文案；`modeSummary(record, lang)` 保留原有 `{ opponent, contract }` 字段形状，并增加 `kind: 'difficulty' | 'persona'` 供标题区分。`opponentCopy` 继续兼容旧引用，逐步委托统一转换。
- 开场和牌桌采用本局锁定的模式；结果、复盘和分享采用对应记录的 mode。新局展示「难度」，旧局保留「对手」人格说明。JSON 延用原 mode 字段。
- 样式沿用白纸黑墨，复用现有选项卡布局并精简首页高度；不新增插画、动效模块或运行时包。

## 评估与验证设计

单位回归覆盖固定构牌场景、每档合法行动矩阵、候选调用上限、观察去重与重开清空、隐私字段访问保护、超时样本排除、强弱牌费用与灾厄边界、旧归档与新难度显示。

整局比较通过既有真实引擎模拟器，将各难度作为引擎对手，分别对固定的 `legacy` 和 `current` 玩家基准。每个种子交换相同两组数字，发牌与策略随机流分离；从对手视角报告胜平负和收益，不能误把玩家得分当作难度得分。基准玩家保持冻结，三档按同一位置和时间节奏对比。

开发使用种子 1–100；参数冻结后独立使用 10001–10100，每种组合每个种子换边，两个基准共 1,200 局独立验证。报告胜平负、得分率与配对区间、进入耐息前 AIR 收益、无解、灾厄、每步守恒和计算开销，同时保存源码哈希和环境。独立验证不参与继续调参；若趋势不足，保留本次失败结果，采用新的未使用区间复核后续修订。

难度顺序结合共同基准表现、配对收益和固定决策场景判断；总体趋势不成立则继续修正，不能用进攻次数替代强度。区间重叠时如实说明证据强度，机器人样本不代表真人胜率。另做跨换罐的慢节奏整局，验证计时与观察不破坏账户或完成局。

浏览器回归包含桌面、390px 根路径和 320px 项目子路径，中英文三档、固定目标映射、旧偏好忽略、各难度终局、复盘及分享。性能测量留在开发工具与浏览器，game 不访问平台时钟。最终运行完整工程检查与相关浏览器回归，真机流畅度和真人挑战感单独记录实际执行范围。

## 技术决策与边界

| 决策                              | 理由                                     |
| --------------------------------- | ---------------------------------------- |
| 难度共享策略与显式预算            | 三档差异可复现，也能在相同局面作对照     |
| 公开观察独立于正式记录            | 保持记录器只记事实的依赖方向与信息隔离   |
| 旧 mode 字段容纳新 ID，保留旧显示 | 既有完成局无需迁移或改写，导出与分享一致 |
| 动作先通过引擎再成为样本          | 非法、重复或过期操作不能污染学习依据     |
| 固定节点预算，旧函数默认路径保留  | 搜索可控，既有基准和测试保持可解释       |
| 困难仅本局适应，少量样本平滑回退  | 五轮样本较少，限制过拟合与异常跳变       |
| 使用模型收益门槛                  | 融合打法仍受费用、灾厄与生存储备约束     |

所有 Spec 功能在上述模块有明确归属。上文的模块划分、接口和评估方式已按获批方案实施。原计划中的「设计审批后再实施」描述的是历史流程，不表示当前仍有待审批或待启动的开发工作；早期独立挑战/契约展开方案也已被固定映射取代。
