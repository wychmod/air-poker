# AIR POKER 八页样式与交互动效详细规划

- 版本：V2.1，2026-10-24；在已批准的八页规划上统一白纸黑墨主题。
- 状态：用户已批准 V2.1 纸白主题修订并要求实施；V2.0 的八页运行界面、独立教学、对战反馈与复盘已接入。V2.1 改动与本次验证单独记录，具体采用范围、验证证据和增强项见 [实施记录](harness/ui-v2-implementation.md)。
- 本轮明确要求：首页、开局过场与其余正式页面统一白纸黑墨漫画风格；保留指定参考的双人对峙、圆桌与水下气氛；具备对战游戏的卡牌与事件反馈；正式牌桌清晰、直观、元素有取舍。
- 实现基础：沿用真实对局、交替下注、实时供气、耐息与完整记录；独立动态漫画示例保留。本文仍作为目标规格，实施差异与未测项目以实施记录为准。
- 页面数量：P01 首页、P02 游戏介绍与规则、P03 教学、P04 对战、P05 胜利、P06 失败、P07 平局、P08 复盘。详细规则归入 P02 的阅读视图，耐息归入 P04，不增加第九页。
- 当前规则以 [当前规则](rules/current.md)、源码及测试为准；旧版页面方案中每轮呼吸扣费、部分有效牌参战、五轮按余额判胜等描述不沿用。

## 1. 视觉主张与六张参考图的具体用途

整体体验是一部可以操作的水下漫画：进入时感到对峙，操作时感到纸牌有重量，摊牌时看清比较，结束时得到明确的情绪落点。每个页面有一个主动作，辅助动效围绕它展开。

| 页面     | 主动作               | 画面基调                           |
| -------- | -------------------- | ---------------------------------- |
| 首页     | 对峙、邀请入场       | 纸白场景、墨线双人圆桌、中央留白   |
| 游戏介绍 | 展开三个关键概念     | 白纸、三栏图示、两侧人物           |
| 教学     | 人物把牌递到练习台   | 纸白练习台，右侧墨线人物有张力     |
| 对战     | 选牌、出牌、结算     | 纸白中央牌桌、墨线分区、事件反馈   |
| 胜利     | 人物破开画面         | 白底胜利海报、抬手姿态、斜向动势   |
| 失败     | 压力收拢后安静       | 纸白底、局部密网点、少量暗红边线   |
| 平局     | 双方归于平衡         | 对称构图、水平水纹、克制运动       |
| 复盘     | 沿事实追踪资金与牌面 | 纸面档案、事件定位、逐笔解释       |

### 1.2 统一样式规格

- 主色：纸白 #F3F2EE、墨黑 #171917、次级灰 #757870、分隔线 #D8D8D0。八页、导航、浮层和开局过场以纸白为底；墨黑用于标题、主按钮、牌背与局部插画阴影，深墨 #0D1010 仅用于必要的局部重墨。水光、气泡和网点使用灰阶；暗红 #9C3737 用于风险与损失，红黑花色有独立符号辨识。
- 中文标题用宋体/明朝体气质；正文和按钮用清楚的黑体；数字使用等宽数字。标题装饰不影响点数、花色、金额与计时的辨识。
- 桌面展示标题 64–104 px，内容页标题 36–48 px；手机展示标题 40–56 px，内容标题 26–32 px。正文 15–16 px，关键标签不小于 12 px，计时与主要 AIR 数值 24–32 px。
- 主按钮为明确的墨黑底、纸白字矩形，配一个短箭头；次按钮使用墨线框或文字。常规操作高度 44–52 px；危险动作与确认区留出间距。
- 使用 1 px 分隔线、2 px 选中线、少量纸影和可控墨边。插画边缘可以粗粝，卡牌内容边界和点击区域必须清楚。
- 桌面主内容宽度约 1180–1240 px；牌桌不为铺满屏幕而拉远卡牌。手机使用单列和自然滚动，底部固定操作区预留自身高度与安全区。
- 同一页面同时只有一个主要事件动效。人物、水光属于低强度背景；牌面、数字、按钮与正文不持续漂浮。

## 2. P01 首页：纸白对峙，中央一个明确入口

### 2.1 首屏构图

桌面以 1440 × 900 为参考，顶部导航 64–72 px；人物各占画面外侧约 24%，桌面位于下部约 20%，中间约 48% 保留给标题、短句和开始按钮。人物脸部不被标题裁掉；中央背景压低细节和对比，以纸白留空；墨黑标题和主按钮保持最清楚。圆桌用灰阶透视、墨线桌沿和轻纸影表达，不铺整屏暗底。

```text
┌ AIR POKER ───────────────────── 游戏介绍  新手教学  设置 ┐
│                                                         │
│  左侧人物          A I R  P O K E R          右侧人物   │
│                    你下注的，是下一口空气。              │
│                                                         │
│                       [ 开始对局 → ]                    │
│                    了解玩法 · 先练一次                   │
│                                                         │
│                  ─── 水下圆桌与微光 ───                  │
│  本地单人 / 双方各25罐 / 五轮后耐息      最近完成局 ↗    │
└─────────────────────────────────────────────────────────┘
```

主操作“开始对局”；介绍与教学为次入口。最近完成局只显示真实已有记录，采用一行摘要；不会扩展为战绩仪表盘。教学尚未实现时不展示失效入口。

### 2.2 动效分镜

| 时间/触发     | 画面动作                                            | 最终状态                               |
| ------------- | --------------------------------------------------- | -------------------------------------- |
| 首帧          | 背景、标题和可操作按钮立即有可读状态                | 图片未完成也可操作                     |
| 0–250 ms      | 桌沿的一条浅灰水线从中央向两侧展开                      | 桌沿固定                               |
| 150–500 ms    | 两侧人物分别从外侧收进约 12 px                      | 人物停在两侧构图位置                   |
| 250–650 ms    | 标题遮罩轻展开，短句降低位移跟进                    | 文本保持静止                           |
| 循环          | 人物异步轻浮 3–5 px，灰阶泡分小组上升，浅水纹缓慢偏移 | 8–12 秒衔接循环，桌面与标题固定        |
| 按钮悬停/聚焦 | 边缘细线延长，箭头前进约 4 px                       | 清楚显示焦点                           |
| 开始点击      | 按钮压下约 2 px；横线扩为短分镜过渡                 | 接入既有开局时序，不额外延长正式局等待 |

不要把首页背景上的固定插画纸牌变成假发牌区。真正可操作的数字牌仅在正式对战或教学中出现。

### 2.3 手机与异常

手机保留两侧上方的人物头肩、中央标题和下方开始按钮，桌面透视只留下沿一段。导航收为“介绍”和菜单；页面主按钮在首屏可达。低动态模式保留完整构图，只做即时选中/按下状态。资源失败时用纸白底、墨黑标题、说明和主按钮维持入口。

## 3. P02 游戏介绍与规则：白纸三栏，一分钟理解核心

P02 的默认视图叫“游戏介绍”，详细规则通过页内切换“完整规则”进入；返回时保留来源和阅读位置。局内从帮助入口打开相应规则浮层，关闭回到原对局。

### 3.1 介绍视图

沿用用户参考的白纸、两侧人物与三栏关系。页首高度适度收紧，三栏在桌面一屏内可读；每栏一幅图示、一句结论、一个“看演示”。下方是“进入教学”和“开始对局”。

```text
┌ AIR POKER ─────────────────────────────── 返回首页 ┐
│                       游戏介绍                    │
│             先理解目标，再承担每一次下注。         │
│                                                    │
│  01 数字与成手   │ 02 空气与下注  │ 03 摊牌与风险 │
│  [五张牌→点数和] │ [储备→底池]   │ [两手牌比较]  │
│  数字是目标和。  │ 用未开罐下注。│ 牌型决定输赢。│
│  [看演示]        │ [看演示]      │ [看演示]      │
│                                                    │
│  [查看完整规则]         [进入教学] [开始对局 →]   │
└────────────────────────────────────────────────────┘
```

参考图中的“灾厄决胜”改为“摊牌与风险”，把灾厄放在条件说明里；不引入图中没有实现的 RANKING 等菜单。

### 3.2 三段不同的演示

1. 数字与成手：五张牌以 35–45 ms 间隔展开；点数沿细线连到目标和。用 4♠、4♥、4♦、5♣、7♠ 解释 24 与三条，再提示目标值与牌型强弱分开判断。
2. 空气与下注：未开储备的一组符号进入底池，当前供气罐留在原位。以当前轮到玩家、双方匹配资源充足、底池 2 且无应跟额的案例解释加注增量上限 1；对方跟注后继续行动。
3. 摊牌与风险：两手牌翻开、比较相关牌加框；同一实体牌才出现连线；满足灾厄条件的例子再显示实际烧毁。不同花色的同点牌不连在一起。

默认完整静态图，点击后仅播放所选一段，约 1.2–2 秒后停在结果，按钮变为“重播”。三段不并行循环，背景人物只保留极弱运动。

### 3.3 完整规则视图

桌面为左侧约 200 px 章节导航、右侧正文；手机改顶部章节选择与单列正文。章节包括回合流程、数字与完整五张成手、交替下注、实体牌与灾厄、供气与耐息、结束与账目。正文中的例子可以展开静态步骤，不依赖观看动画才能理解。

无解数字仍可选，失败不消耗实体牌；五轮后先耐息；未开罐为零与供气结束分开说明。只有已经通过引擎的终局才进入胜/负/平结果页。

## 4. P03 教学：人物把牌递到你面前

### 4.1 构图与任务层级

参考“去文字背景.png”的伸手方向。桌面左侧约 62% 为稳定纸白练习台，右侧约 38% 保留人物脸、手势与一段速度线；手可以越过装饰分界，但不覆盖卡牌和按钮。人物后景保留漫画动线，练习台背景清空。

```text
┌ ← 离开教学                         练习 1 / 4 ┐
│                                                │
│  选一手满足目标的牌。           [伸手人物]     │
│                                                │
│  目标 24                      手势指向练习台   │
│  [完整候选一]                                  │
│  [完整候选二]                                  │
│                                                │
│  提示：选择整手，再确认锁定。                   │
│  [重新练习]                 [确认这手牌 →]     │
└────────────────────────────────────────────────┘
```

一屏只要求一个动作。进度、任务、练习对象、结果解释和下一步依次排列；提示在对象旁，不用大面积蒙层遮住牌面。

### 4.2 四项练习

| 练习         | 操作目标                             | 动效与解释                                                            |
| ------------ | ------------------------------------ | --------------------------------------------------------------------- |
| 选数字与锁定 | 认识数字牌、完整候选和确认锁定       | 牌叠从手势方向递入约 240 ms，候选展开；点数和一次高亮，锁定后整手归位 |
| 跟注与加注   | 区分应跟、再加、本次支付和支付后余额 | 随操作展开等式，确认后空气标记移入底池；行动方交替                    |
| 失败与灾厄   | 区分成手失败、普通弃牌、实体重叠灾厄 | 三种情况使用独立短分镜；账目解释实际损失，失败牌不飞入弃牌堆          |
| 呼吸与耐息   | 区分未开储备、当前罐供气、缺氧宽限   | 用“推进练习时间”按钮观察开罐与耗尽；标明正式局按真实时间处理          |

引导线从手势方向画向当前对象，约 250–300 ms 后停止。完成操作时对象对齐、出现简短确认文字；解释随后展示。错误时指出具体条件，不用震屏或无依据扣资源。

练习是独立实例，固定例子都需符合当前规则；可重练、离开和手动推进，不写正式胜负。教学完成显示已练过的四件事，提供“开始正式对局”和“再练一次”。

### 4.3 手机

人物压为顶部 110–150 px 的横向漫画框，只保留脸和手势；练习区在下面全宽展开。卡牌选择按整手进行，单张查看仅解释点数/花色，不暗示能拆开重组。底部确认区预留占位，长说明自然滚动。

## 5. P04 对战：一张中央牌桌，三个稳定区域

### 5.1 明确的信息取舍

常驻区域只有顶部资源栏、中央当前任务、底部动作区。资源栏回答“我还有多少未开 AIR、当前能呼吸多久、底池多少”；中央回答“轮到谁、现在做什么”；底部回答“这一步会付多少、点击哪里”。

详细日志、完整回合轨迹、弃牌图鉴、规则和五账户图表按需展开。头像缩为身份标记；人物仅在画面外侧或后景低对比出现。阶段说明用一个短标签与一句任务表达，避免把所有阶段做成多排常驻仪表。

选择、锁定和下注各有一个最明确的确认动作；过牌/跟注等合法替代操作仍清楚可见。牌面和当前任务占主要视觉面积，边缘人物不压缩这块空间。

### 5.2 桌面基准布局

1440 × 900 基准：顶部导航约 64 px，资源栏 80–88 px，中央牌桌为主要弹性区域，操作区约 110–144 px。内容最大宽约 1180 px；高度不足时允许自然滚动，不缩小关键字体。

```text
│               对手 · 公开目标36 · 成手隐藏               │
│                      [背][背][背][背][背]                 │
│                                                          │
│                       轮到你下注  24s                    │
│                       需要跟齐 2 AIR                     │
│                                                          │
│                   本轮已投：你2 / 对手4                  │
│                                                          │
│                   [4♠][4♥][4♦][5♣][7♠]                  │
│                     你的目标24 · 三条                    │
```

### 5.3 手机基准布局

### 5.4 数字牌和扑克牌的实体感

数字牌：纵向硬纸/金属卡轮廓，中央大数字，顶部小位置序号；不使用扑克花色。同值数字按开局的独立位置保留身份，已用位置留小轮廓，整局不补发。

实体扑克牌：纸白牌面、真实点数与花色、薄墨边、小幅圆角和短纸影；牌背用代码绘制稀疏菱形/网点纹。关键数字不依赖贴图，牌面放大后仍清晰。比较和下注时卡牌保持接近正面，手牌不做遮挡数值的大幅扇形。

候选：每一项是一整手五张，标题有牌型、点数和、暂选状态。选择作用于整项；单张查看只用于辨认，不提供当前玩法没有的逐牌换牌或拖拽组牌。

### 5.7 下注：金额必须在点下之前说清楚

常驻公式为“应跟 + 再加 = 本次支付”，下方显示支付后未开余额。加注输入只代表再加的增量，确认按钮显示实际支付总额。

例：底池 6、你已投 2、CPU 已投 4，应跟 2；输入再加 2，按钮写“加注 · 支付 4”，支付后你未开 AIR 从 22 变为 18。这个示例同时满足半池增量上限和总资金核对。

无压力时显示过牌，有压力时显示跟注。快捷“最大合法投入”仅在可用时出现，先填入预览；只有引擎确实允许的全押动作才使用相应名称，不将普通最大加注误称为全押。

动作被接受后数值立即更新；用一个空气符号加实际数量（例如 ×4）沿短路径从未开储备移动到中央底池，约 260–360 ms；底池旁短暂显示“你投入 4”。当前供气罐始终留在供气区。CPU 动作发生后再播其反馈，跟注后可能继续轮到玩家。

行动提示区同时显示“轮到你”和剩余秒数；CPU 阶段使用中性“对手行动中”。最后 10 秒提高文字对比并提醒一次，根据应跟压力明确超时过牌或弃牌；不循环闪烁。供气秒数与行动秒数分开命名，计时变化不重建金额输入和焦点。

### 5.8 摊牌、灾厄与回合账目

顺序为已公开牌面 → 牌型 → 决定比较的关键牌/踢脚 → 必要时同实体重叠 → 本轮结果与实际账目。重点高亮使用细框、短连线和文字，不让所有牌同时发光。允许直接查看完整结果，不强制看完演出。

灾厄仅在合法条件发生时表现：连线约 180 ms，局部碎墨/边线约 250 ms，之后保留静态损失说明。参考插画的冲击感放在小范围后景，金额保持可读。弃牌、平局、单方成手失败不套用灾厄效果；实际 burned 为零不画虚假的气罐损失。

账目默认只列本轮投入、底池收款、退款、烧毁和净变化；呼吸开罐有独立原因标签。详情放入记录入口，不能把收到的整池当成净赚。余额直接显示真实结果，不用缓慢滚动数字造成“现在到底剩多少”的歧义。

双方失败：保留轮次、目标和底池，失败草案收起；实体牌不飞入已用区，重新构造不重复下注。双无解：显示退款与耐息原因，按引擎状态进入耐息。

### 5.10 一眼可懂的边界反馈

- 无候选：说明“当前数字无法组成合法五张牌”，保留主动失败入口；无解不是自动重开理由。
- 构造超时：显示失败原因并按真实阶段推进；已选实体牌不因此消耗。
- 过期下注：旧操作立即失效，显示已经按超时规则处理；不给新的 30 秒。
- 只读查看：规则、弃牌和记录抽屉显示当前行动剩余时间，关闭回原任务，时钟继续。
- 低动态模式：卡牌直接进入选中/锁定/公开的最终状态，保留边框、标签、资金原因和所有按钮。

```text
└──────────────┴─────────────────────────────────────┘
```

列表区分已结算、重做尝试、作废和中断；默认定位当前快照的最近事实，结束局可从最后事件查看。只统计真正完成的回合，不能把中断轮算为完成。

### 9.2 交互与动效

点击回合后，内容区约 150–200 ms 短切换；选中事件通过细线定位对应卡牌与账目行。资金转移使用“账户 → 账户”路径，约 250–400 ms；停在静态金额与原因，重复点播也不改变任何账目。

只有记录足以支持的事件才能提供只读演示播放。播放、暂停、拖动使用记录中的时间或明确事件刻度，不重新运行 AI、不派发对局动作，也不补造未记录的中间过程。默认进入时静态可读，用户主动播放后才演示。

五账户展开为：玩家未开余额 + CPU 未开余额 + 底池 + 累计已开呼吸罐 + 累计烧毁 = 50。底池收款、净变化、退款和开罐原因分别标注，不能拿累计收款冒充盈利。

当前局记录标明“打开时快照”，刷新由用户明确触发，查看期间真实游戏时钟继续。未揭示 CPU 内容保持隐藏。最近完成局、JSON 导出、空态与保存失败提示继续使用现有能力，不承诺恢复未完成对局。

手机回合选择为可展开列表/紧凑标签，事件、牌面与账目纵向排列；五张牌完整可见，复杂表格转为逐笔账单。图表有文字/表格等价信息，状态不只靠颜色表达。

## 10. 哪些内容用代码画，哪些需要分层素材

| 内容                                   | 实现方向                             | 理由与限制                                       |
| -------------------------------------- | ------------------------------------ | ------------------------------------------------ |
| 数字牌、扑克牌、牌背、点数与花色       | HTML/CSS/SVG                         | 可缩放、可交互，文字始终来自真实数据             |
| 选中框、按钮线条、牌面纸影             | CSS                                  | 短响应，聚焦/触屏有等价状态                      |
| 出牌路径、比较线、点数和连线、资金流向 | SVG/CSS                              | 可精确对应对象与事件，结束后保留静态解释         |
| 桌沿反光、分镜框展开、标题揭示         | CSS 遮罩或 SVG                       | 统一漫画语言，局部发生，不影响正文               |
| 呼吸泡、前景泡、水光、浮尘、一次性碎墨 | 单个场景 Canvas 或轻量 SVG           | 稳定参数按时间绘制；装饰不承担账目或私密信息     |
| 当前供气条、缺氧提示                   | 原生 UI + 公开状态映射               | 数值与引擎一致，不由粒子数量推算                 |
| 人物整体轻浮、短进场、景深             | 独立人物图层 + CSS 变换              | 先有干净遮罩，避免人物边缘露出原背景             |
| 发丝、衣摆、手掌、表情的独立变化       | 单独分层、连接处补绘、必要时局部重绘 | 当前整张图不具备这些运动关节，不能用大幅扭曲替代 |

第一批目标是可信的实体卡牌交互和清楚的事件反馈，加上低幅人物运动。更细的人物动作建立在新增素材上，作为增强项。游戏运行时直接绘制当前画面，无须预生成几百张 PNG；逐帧导出可留给另行提出的视频用途。

## 11. 统一动效时序与生命周期

### 11.1 四种节奏

| 层级     | 时长起点   | 使用方式                                             |
| -------- | ---------- | ---------------------------------------------------- |
| 操作反馈 | 120–200 ms | 悬停、聚焦、暂选、按下；对象就地响应                 |
| 游戏事件 | 220–500 ms | 出牌、锁定、支付、翻牌与比较；只在真实事件发生时播放 |
| 叙事入场 | 500–800 ms | 首页、教学分镜、结果人物；按钮立即可操作             |
| 环境循环 | 8–12 秒    | 人物、水光和气泡；决策页面降低强度                   |

开局的页面转场与人物过场统一采用纸白底、墨线分镜和灰阶水纹，在既有约 1350 ms 时序内合并完成，不切回整屏深色，也不把两个独立等待时间相加。任何“跳过表现”只改变展示进度，不改变游戏状态和截止时间。

普通操作优先平顺、短行程的缓出；选牌仅轻微回落，不做大幅弹簧；失败不用摇晃整页；灾厄不使用频繁高亮闪烁。标题、金额、正文和正在编辑的输入框保持稳定。

### 11.2 状态与事件约束

- 表现层只消费公开快照与已发生事件。动作接受后立即更新合法操作和真实金额，视觉副本只解释变化。
- 事件按当前 session、turn/attempt 及事件身份区分，重绘和语言切换不重复播放。新阶段到来时取消已过期演出，不能让旧牌或旧确认遮住新任务。
- CPU 摊牌前的 DOM、可访问描述和粒子/表情逻辑只含允许公开的信息，不在卡背另一面预放私有牌面。
- 一个活动场景统一管理绘制，隐藏时停止装饰绘制，离开时清理循环、观察器和监听；恢复先同步游戏时间，再显示当前事实，不补播长队列。
- 动效暂停、偏好切换、原图对比、只读查看都不是对局暂停。真实呼吸、构造和下注时限继续按引擎处理。
- 玩家输入和键盘焦点在供气更新时保留；抽屉关闭回到触发位置，阶段已结束时转到新任务。

### 11.3 手机、性能与减少动态效果

建议起始预算：首页/结果的装饰粒子桌面约 24–48、手机约 8–16；对战进一步减半。具体数量按实测调整，Canvas 像素倍率上限 2，页面只保留必要画布。避免多个全屏模糊、位移滤镜或巨大逐帧纹理重绘。

减少动态效果时取消景深、人物漂浮与长轨迹，卡牌直接进入选中/锁定/公开终态；金额标签、比较依据和全部按钮保留。系统偏好应默认生效，设置里可调整装饰动效。逐帧变化的时间和输出不连续触发读屏播报。

所有交互支持点击/键盘，无拖拽、悬停或长按专属的关键操作；触控目标至少约 44 × 44 px。资源失败可回退纯色纸面与正常牌面，不能失去开始、下注和返回入口。

## 12. 新增素材和开发顺序

### 12.1 素材清单

| 优先级 | 素材                                               | 用途                         |
| ------ | -------------------------------------------------- | ---------------------------- |
| 第一批 | 无 UI 的首页纸白背景、左右墨线人物层、圆桌线稿层       | 首页和短过场                 |
| 第一批 | 浅纸背景、两侧人物/面罩层                          | 介绍、平局及统一纸面语言     |
| 第一批 | 教学人物/手势分镜、干净练习台                      | 递牌入场与学习焦点           |
| 第一批 | 胜利人物干净层、失败双人横向裁切                   | 两种不同结果构图             |
| 第一批 | 通用纸牌/数字牌/空气符号/比较线/墨痕               | 以代码绘制为主，整个游戏复用 |
| 增强批 | 更高分辨率胜利人物、头发/衣摆/手掌独立层及补绘背景 | 提高大屏清晰度和人物局部运动 |

### 12.2 建议实施顺序

1. 先做通用纸牌、数字牌、按钮、选中状态、短出牌和翻牌；用 P04 的选牌/下注小场景验证“看得懂、点得准、有反馈”。
2. 完成 P04 各阶段布局与卡牌、资金、灾厄、耐息事件；验证真实规则、计时与边界，再复用组件到其他页面。
3. 按指定参考完成 P01 首页、P02 介绍、短过场，建立完整视觉入口。
4. 完成 P05/P06/P07 三种结果构图，串联重玩与现有记录。
5. 升级 P08 复盘展示；利用同一套卡牌与资金演示组件实现隔离的 P03 教学。
6. 在稳定版本上增加更细人物分层和移动端性能优化，逐页验收素材清晰度与负载。

这个顺序将最难的牌桌可读性与交互先验证。开发可按组件和页面分工，但运行模块仍遵守现有职责与依赖矩阵，不把八页和动画重新堆进单个入口文件。

## 13. 可观察的验收要求

以下为设计验收目标。实际已执行场景与未执行项目详见实施记录，不将设计目标等同于全部验证通过。

### 13.1 页面与构图

- 统一主题：八个正式页面、导航、浮层与开局过场均以纸白为底，墨黑用于标题、主按钮与牌背；胜利留白和失败网点/暗红具有不同语义，跳转时无整屏深色主题突变。
- P01：指定参考的双人、圆桌、中央标题关系成立；首屏能找到开始；没有失效教学或虚假记录入口。
- P02：三概念一屏可读，每段演示可单独播放/重播；完整规则可查，灾厄被解释为条件事件。
- P03：右侧人物不遮住练习对象；四项练习可重练、可离开，正式记录与时钟不受练习实例影响。
- P04：任意阶段能明确指出当前任务、行动方、合法操作与费用；常驻信息不需要在左右多个侧栏来回寻找。
- P05：抬手人物形成独立胜利构图，原尺寸清晰度经过检查；结束原因与真实 winner 一致。
- P06：双人参考不造成双方失败的错误含义；原因、相关账目与重玩入口可读。
- P07：有独立平局语义，按真实结果呈现，不用余额或胜场自行决胜。
- P08：每笔变化可定位到事件和账户；中断/作废/尝试与已完成轮次区分；记录播放只读。

### 13.2 交互与规则

- 同一张数字牌从暂选到公开的路径一致；同值不同位置仍可辨认，已用牌不补发。
- 每项候选完整五张可读，选择整手；没有隐藏的第三项或不支持的逐牌编辑暗示。
- 连续切换候选、键盘选择、确认与超时竞争时，高亮、焦点和实际状态一致。
- 下注前能读出应跟、再加、本次支付与支付后余额；转移动效从未开储备出发。
- 跟注后可继续，连续两次过牌、匹配全押或弃牌按引擎结算；动效不提前揭牌。
- 失败重做保留同轮事实，不重复底注、不消耗失败实体牌；合法灾厄只显示实际 burned。
- 五轮后先耐息；未开余额零仍有供气时不提前终局；任何阶段真实耗尽都能中断旧动画。

### 13.3 浏览器与可访问性

- 1440 × 900、较矮桌面、320/360/390/430 px 手机宽度、横屏及 200% 缩放均能完成主要操作；底部操作区不挡住最后一项候选。
- 鼠标、触屏和键盘可完成同一流程；焦点可见，图标和金额有可理解名称。
- 减少动态效果、关闭装饰、切语言、开规则/记录、后台恢复不会重置或延长截止时间。
- 重开、离开与恢复不产生重复绘制、重复支付或重复演出；页面脚本与本地资源无加载错误。
- 运行完整 npm run check，核对发布子路径和资源白名单；真实浏览器验收与自动检查分别记录。
- 在实际设备记录渲染负载、长时间运行与后台恢复结果，未测量前不承诺固定帧率。
