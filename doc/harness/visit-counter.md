## 统计边界

- 计数 key 是固定常量 `air-poker.views`，与部署域名、路径无关：GitHub Pages、镜像站、自定义域名等任意多处部署读取并累加同一个计数器，符合“两处合并”的需求。hits.sh 要求 key 是合法 URI，实测 `air-poker/views` 返回 `Not a valid URI`，`air-poker.views` 被接受，因此 key 写成“域名样式”。要分成两个账本，改 `COUNTER_KEY` 即可。
- `browser/visit-counter.js` 仍以自身模块的上级目录确定站点地址，但该地址只用于判断“是否公网 HTTPS”，不再参与 key 计算。本地 HTTP、回环及常见内网地址不请求服务。首页别名、查询参数和锚点不改变请求地址。
- 一次整页加载只设置一次图片地址；计数节点位于 `#pageContent` 外，切页、语言切换和游戏重开不会再次请求。
- PV 统计图片加载请求，不去重为独立访客，也不保证与真实浏览人数相同；缓存、拦截、重复访问和服务可用性会影响结果。不能恢复接入前的历史访问。
- 2026-11-08 之前使用“域名 + 路径”作为 key，旧计数（`wychmod.github.io/air-poker`）不会迁移到新 key，仍可通过 `https://hits.sh/wychmod.github.io/air-poker/` 的 dashboard 查看。如需让页面数字显示接续，在图片地址追加 `extraCount=<旧值>`：实测该参数只影响显示值（显示 = 实际计数 + 偏移），不写入累计，重复请求不会污染。
- 合并计数的取舍：任何 fork、镜像或第三方克隆都会计入同一账本，无法区分来源。需要按站点分账时，改 `COUNTER_KEY` 或恢复按地址派生。
- 加载中、本地预览和不可用具有文字状态。失败或 8 秒超时后不自动重试，不显示虚假的 0，不阻断游戏；非缓存离开页面清理尚未完成的监听与计时器，bfcache 保留原请求与回调，恢复不重计。
- 外部请求仅为计数图片，采用 `no-referrer`，不发送对局或本机记录。服务方仍能收到常规图片请求的网络信息。
