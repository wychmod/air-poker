# 空气扑克 / Air Poker

纯原生 JavaScript 单人空气扑克原型，可直接部署到静态托管服务。

## 本地运行

使用 Node.js 22 或更新版本：

```sh
npm ci
npm start
```

打开 <http://127.0.0.1:4173>。浏览器通过 HTTP 加载 ES modules；直接双击 HTML 文件不适用。
可用 `AIR_POKER_PORT` 环境变量更改端口。页面本身没有第三方运行依赖，也没有构建步骤。

## 动态漫画游戏界面

八页界面已接入：纸白漫画首页、三概念介绍、四项独立教学、中央对战牌桌、胜利/失败/平局和完整复盘。正式页面与开局过场沿用白纸黑墨，双人对峙、圆桌、气泡和水纹以灰阶呈现，墨黑强调标题、主按钮与牌背。数字牌先暂选再确认，成手按整手选择，下注前展示应跟、再加、实际支付与剩余储备；出牌、锁定、资金转移、翻牌与灾厄由公开的真实状态驱动。

设置中可关闭动效，系统减少动态效果优先；这些设置不暂停真实供气和行动时限。离开未完成对局会确认，完成局支持逐轮、逐次尝试、事件播放与账目导出。实现、验证与限制见 [八页实施记录](doc/harness/ui-v2-implementation.md)。

## 独立动态漫画示例

设置中点击“打开独立动态漫画示例”可查看素材实时动效，支持暂停、重播、进度拖动、强度切换与原图对比。示例与对局独立，详见 [实现与验收](doc/harness/motion-demo.md)。

## 检查与格式化

```sh
npm test
npm run check
npm run format:check
npm run format
```

测试使用 Node 内置测试运行器，覆盖牌型、候选、结算、阶段限制和完整对局的资源不变量。
Prettier 仅用于开发时格式化源码。

`npm run check` 顺序运行语法、架构、回归测试、格式、静态产物与 HTTP 资源检查，失败即停止。
最近一次结果保存在忽略目录 `output/harness/latest.json`。单独检查产物时先执行 `npm run build`，再执行 `npm run check:smoke`。
HTTP 检查不运行页面脚本；交互改动仍需浏览器验收。

协作约束见 [AGENTS.md](AGENTS.md)，文档入口见 [doc/README.md](doc/README.md)，完整工程说明见 [Harness](doc/harness/README.md)。

## 代码组织

| 路径                                            | 职责                                             |
| ----------------------------------------------- | ------------------------------------------------ |
| `app.js`                                        | 浏览器入口、事件委托、页面切换、倒计时与语言存储 |
| `game/data.js`                                  | 固定花色与点数定义                               |
| `game/cards.js`                                 | 实体牌和合法候选生成                             |
| `game/deal.js`                                  | 独立数字牌生成与来源证明                         |
| `game/ai.js`                                    | 独立选牌及仅凭己方私牌与公开信息下注             |
| `game/records.js`                               | 完整事件、轮次事实、逐笔空气账户与归档校验       |
| `browser/record-store.js`                       | 最近完成局本机存储与失败降级                     |
| `ui/record.js`                                  | 只读记录、账目与时间线渲染                       |
| `game/breathing.js`                             | 供气、自动换罐、缺氧宽限与实际存活计算           |
| `browser/match-clock.js`                        | 单调时间、后台恢复与对局时长同步                 |
| `game/betting.js`                               | 合法下注、应跟额、半池上限和纯状态转换           |
| `browser/turn-clock.js`                         | 按行动编号计时、CPU 调度、后台恢复               |
| `game/rules.js`                                 | 牌型比较、有效牌过滤、结算计算                   |
| `game/engine.js`                                | 私有对局状态和动作合法性                         |
| `ui/render.js`                                  | 页面组合、语言、焦点与增量供气渲染               |
| `ui/battle.js`、`ui/pages.js`、`ui/tutorial.js` | 对战、叙事与独立教学模板                         |
| `ui/review.js`                                  | 回合/尝试导航、事件事实与五账户复盘              |
| `browser/scene-motion.js`                       | 公开事件动画、Canvas 环境与绘制生命周期          |
| `i18n.js`                                       | 中英文文案；渲染时按 key 翻译                    |
| `styles/`                                       | 基础、页面、牌桌样式；`styles.css` 统一导入      |
| `tests/`                                        | 无浏览器依赖的规则和引擎回归测试                 |

`createGame()` 返回 `getState()`、`getRecord()`、`dispatch(action)` 和 `reset()`。`getState()` 返回独立快照，隐藏 CPU 未公开数字与摊牌前私牌；
调用者通过动作更新对局，错误阶段、参数或重复提交返回 `false`，不修改状态。
游戏模块不访问 DOM、浏览器存储、翻译或计时器。完整记录通过 `getRecord()` 按需读取独立快照，进行中继续隐藏 CPU 未公开成手；`getState()` 只附带轻量账户摘要。

## 当前玩法范围

双方开局各持五张独立数字牌，整局逐张消耗；CPU 在玩家选择前预先锁定。实体牌基于共享剩余牌库，显示至多三个合法完整五张推荐。上层有 60 秒时限，可主动失败保留实体牌；单方失败输掉底池，双方失败同轮重做，不重复扣款。

下注采用交替行动、应跟压力、连续两次过牌、半池增量上限和可匹配全押。每次玩家行动 30 秒，CPU 使用公开信息与自己的私牌作启发式决策。

双方总资源各 25 罐，开局各开一罐呼吸，余 24 罐可下注。每罐近似 300 秒，耗尽自动更换，已开罐不能下注；不再按回合扣呼吸费。五轮或无法继续下注时进入耐息，可快进到首次供气及数字版缺氧宽限耗尽；按实际存活判胜，未开余额为零不等于立即死亡。

完整行为与改编边界见 [当前规则](doc/rules/current.md)，来源见 [规则核对](doc/rules/audit.md)，本轮设计与证据见 [生存逻辑](doc/rules/survival/spec.md) 和 [验收](doc/rules/survival/checklist.md)。未模拟个人生理、残气隐藏和剧情干扰，不能称为完整复刻。历史拆分与下注记录分别保留在 doc/maintainability/ 和 doc/rules/betting/。

## 完整记录与空气账目

对局页点击“记录”、结算页点击“查看复盘”，或首页点击“最近完成局”查看快照。可展开每轮目标、构造尝试与成手、结算依据、实际收款和烧毁，以及全部行动时间线与逐笔空气转移；支持中英文与 JSON 导出。查看不暂停呼吸或行动计时，可手动刷新本局快照。

逐笔账户从双方各 25 罐开始核对，未开余额、底池、已开呼吸罐和灾厄烧毁合计始终为 50。收下底池与净变化分别统计，避免把收款误当净赚。

本机仅保存最近一个完成局；重开不覆盖，直到下一局完成。刷新可查看已保存结果，但不恢复未完成对局。存储失败时本次完成记录仍在内存，可导出保留。详见 [记录方案](doc/rules/records/spec.md)与[验收](doc/rules/records/checklist.md)。

## 部署

`npm run build` 按白名单将 HTML、JS 模块、CSS 和生成图片复制到 `dist/site/`，没有代码编译步骤。
Pull request 与 main 推送运行完整 harness 检查；GitHub Pages 发布前使用同一检查命令，再上传 `dist/site/`。
开发依赖、本地服务器、测试、工程文档和待评审设计预览不进入部署产物。
